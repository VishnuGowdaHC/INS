1. Executive Summary & Overview

This document provides an end-to-end technical overview and workflow analysis of the Tiger-192 cryptographic hash engine and its verification of the Strict Avalanche Criterion (SAC). The project was constructed as a core module in Information and Network Security (INS) to study and visualize how non-linear substitution, key expansion, and multi-pass register transformations achieve optimal confusion and diffusion.

Core Purpose: Demonstrate that when an arbitrary input string undergoes a minimal 1-bit or 1-character mutation, the resulting 192-bit cryptographic hash digest undergoes an unpredictable, chaotic transformation flipping approximately 96 out of 192 bits (50.00% ± standard deviation ~6.93 bits).

2. Theoretical Foundations

Shannon's Confusion & Diffusion

Confusion: Obscures the mathematical relationship between the plaintext message and the digest. Tiger achieves this through four precomputed S-boxes ($T_1, T_2, T_3, T_4$) containing 256 64-bit entries each.

Diffusion: Spreads the statistical influence of each individual plaintext bit over the entire output digest. Tiger achieves this through pass multipliers (5, 7, 9) and an invertible key schedule.

Strict Avalanche Criterion (SAC)

Formulated by Webster and Tavares (1985), SAC states that if a single input bit is complemented, each output bit must change with probability $p = 0.5$.

For $n = 192$ output bits:
• Expected mean: $\mu = n \cdot p = 192 \times 0.5 = 96\text{ bits}$
• Theoretical variance: $\sigma^2 = n \cdot p \cdot (1 - p) = 48$
• Standard deviation: $\sigma = \sqrt{48} \approx 6.928\text{ bits}$

4. Detailed Algorithmic Step-by-Step Specification

Phase 1: Message Padding

Tiger handles messages of any bit length. To align with 64-byte block boundaries and prevent length-extension attacks:

  1. Append byte 0x01 (single 1-bit followed by seven 0-bits) to the end of the message.
  2. Append $k$ zero bytes (0x00) where $k$ is the smallest non-negative integer satisfying: $$(L + 1 + k) \equiv 56 \pmod{64}$$
  3. Append the original message bit-length ($L \times 8$) as an 8-byte (64-bit) unsigned integer in little-endian order.

Phase 2: Sub-Round Transformation Function

The sub-round function _round(a, b, c, x, mul) is the mathematical core of Tiger. It uses eight bytes of register $c$ to perform lookups across four 64-bit tables: 

def _round(a: int, b: int, c: int, x: int, mul: int):
    c ^= x
    a = (a - (T1[c & 0xFF] ^ T2[(c >> 16) & 0xFF] ^ T3[(c >> 32) & 0xFF] ^ T4[(c >> 48) & 0xFF])) & MASK
    b = (b + (T4[(c >> 8) & 0xFF] ^ T3[(c >> 24) & 0xFF] ^ T2[(c >> 40) & 0xFF] ^ T1[(c >> 56) & 0xFF])) & MASK
    b = (b * mul) & MASK
    return a, b, c

Phase 3: The Invertible Key Schedule

To prevent slide and symmetry attacks, the 8 block words $x[0 \dots 7]$ are scrambled between Pass 1 and Pass 2, and again between Pass 2 and Pass 3: 

# Key Schedule (Transforms x[0..7] in place)
x[0] = (x[0] - (x[7] ^ 0xA5A5A5A5A5A5A5A5)) & MASK
x[1] ^= x[0]
x[2] = (x[2] + x[1]) & MASK
x[3] = (x[3] - (x[2] ^ ((~x[1] & MASK) << 19 & MASK))) & MASK
x[4] ^= x[3]
x[5] = (x[5] + x[4]) & MASK
x[6] = (x[6] - (x[5] ^ ((~x[4] & MASK) >> 23))) & MASK
x[7] ^= x[6]
# Second cascade: x[0] += x[7], x[1] -= ..., ending with XOR 0x0123456789ABCDEF

8. Real-World Applications & Technology Stack

Where Tiger-192 is Used
  • Direct Connect (NMDC & ADC): Used as the Tiger Tree Hash (TTH) root to uniquely index and verify file chunks in peer-to-peer distribution.
  • Gnutella2 & Shareaza: Employs TTH Merkle trees for parallel chunk verification and repairing corrupted downloads.
  • Forensic Checksum Utilities: Integrated into forensic tools (such as RHash) for verifying digital evidence integrity.
  • Academic Research: Demonstrating 64-bit S-box diffusion and multi-pass Feistel-variant structures.
Technology Stack
  • Core Backend: Pure Python 3.8+ Standard Library (Zero external packages required).
  • Web Server: Built-in http.server.ThreadingHTTPServer with CORS support.
  • Client-Side Engine: Modern JavaScript ES6+ utilizing native BigInt and BigUint64Array for offline calculation.
  • Interface: Vanilla Semantic HTML5 & Custom Modern CSS (100vh fit, interactive matrix grid).

9. How to Provide Inputs (User Guide)

The system provides four flexible input mechanisms catering to interactive visual exploration, automated terminal execution, RESTful integrations, and direct Python scripting:

Method 1: Interactive Web Application (Recommended)

Start the web server using:

python main.py --web    # Starts server and opens browser automatically at http://localhost:8000
  • Live Keystroke Typing: Type any text into the Message 1 or Message 2 boxes. The client engine computes the 192-bit hash and matrix diff in under 1 millisecond.
  • "Change 1 Character" Button: Mutates a character in Message 2 to instantly view single-character avalanche.
  • "Flip 1 Bit" Button: Inverts exactly one binary bit in Message 2 to inspect pure single-bit diffusion.
  • "Clone Message 1" Button: Clones Message 1 to confirm that identical inputs produce 0 differing bits (0.00%).
  • 192-Bit Matrix Inspection: Click on any matrix cell to inspect its bit index (#0 to #191), byte number, and matching status.
  • Statistical Simulation Tab: Configure trial counts (50 to 1000) and click Run Statistical Test.
  • Self-Test Vectors Tab: Click Verify All Test Vectors to test official reference test vectors.

Method 2: Command-Line Interface (CLI)

# Run automated self-test, avalanche demo, and 500-trial Monte Carlo simulation:
python main.py --cli

# Launch web server on custom port:
python main.py --web --port 8080

Method 3: HTTP REST API Endpoints

# 1. Compute Hash for an input text
curl -X POST http://localhost:8000/api/hash \
  -H "Content-Type: application/json" \
